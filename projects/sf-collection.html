一、业务背景：智驾采集车队在管什么

自动驾驶模型的训练离不开真实路采数据：车队开着装有激光雷达、摄像头、毫米波雷达的采集车，在城市道路、高速、乡村公路上按标准跑，然后把采集硬盘寄回公司。这套系统服务的，就是这样一个车队。

过去这类车队靠"表格 + 群聊"管理，痛点很集中：

  • 任务靠人肉排：谁、开哪辆车、跑哪条路线、今天要跑多少公里，全靠口口相传；
  • 合规靠自觉：测绘作业证、备案登记通知书、营业执照等资质要定期点检，漏一项就可能停线；
  • 资产靠电话：硬盘发出去了没有、寄回来没有、数据量对不对，基本靠催；
  • 过程是盲区：采集员现在在哪、是否偏航、轨迹是否异常，管理侧一无所知。

系统的目标，就是把车队运营数字化、流程化、可回溯。

六、工程上的几个亮点

  1. 单文件后端 + 内联迁移：没有迁移工具，靠 PRAGMA table_info 检查列、缺失则 ALTER TABLE ADD COLUMN——快速迭代也能安全演进；
  2. 流式上传：1MB 分块写盘，大文件不 OOM，上传与落盘并发；
  3. 水印 + OCR 一条链：上传照片自动加"智驾采集"角标 + 人员/时间/坐标/地址面板；面单照片 OCR 自动提取顺丰单号（SF 开头 12 位），再调顺丰接口查路由（MD5 数字签名）；
  4. 看板与效率：总览卡 + 7 日里程趋势 + 异常数；效率按时间 / 对象 / 道路类型三维统计；
  5. 部署朴素到极致：requirements.txt 只写 2 个依赖、venv 实际 40 个；uvicorn 2 workers + nginx 一条命令上线。

七、诚实复盘：Vibecoding 的代价

速成不是魔法，这套系统也把 Vibecoding 的另一面暴露得淋漓尽致：

  • 单文件的代价：10,340 行的 main.py，函数多了之后，阅读、协同、单测都变难；
  • 密钥管理裸奔：顺丰 / 高德 / 丰图 / DeepSeek 的密钥明文种在代码或配置里，默认密码是统一常量——MVP 阶段够用，生产必须重构；
  • 依赖与声明脱节：requirements 声明 2 个、实装 40 个，靠 try/except ImportError 逐层降级；
  • 开发痕迹进产物：AI 工具的权限配置被打进构建目录、Vim 交换文件与源码并列——快，但没时间收拾。

这些"脏"是速成系统的常态。重要的不是假装它不存在，而是知道它在哪里、什么时候必须还债。

九、产品经理复盘：五条值得抄的判断

  1. 先跑通纵向切片，再铺功能面：第一版只做"建任务 → 执行 → 看板"，能演示就能谈需求；
  2. 把合规做成点检项，而不是文档：测绘作业证、备案通知书是行业硬门槛，产品化后变成每天可执行的清单；
  3. 状态机是流程系统的脊梁：先定状态与流转，页面和看板只是它的投影；
  4. 过程资产化：轨迹、标注、审计日志、版本路线图，让每次运营都可回溯、可复盘；
  5. 知道什么时候还技术债：2 天速成解决"能用"，生产化解决"扛得住"——把"脏"记录在案，按节奏还。

结语

2 天能速成一个能上线的业务系统吗？能。但真正的价值不在那 2 天，而在之后 3 个月里，这个系统一直跟着真实车队跑、被使用、被迭代。Vibecoding 改变的不是"写代码的速度"，而是从想法到可用产品的距离——这才是产品经理最该抓住的东西。

1. Business Context: What an ADAS Collection Fleet Manages

Autonomous-driving models need real road-collection data: fleets run instrumented vehicles (LiDAR, cameras, mmWave radar) across urban roads, highways, and rural roads following collection standards, then ship the hard disks back. This system serves exactly such a fleet.

Before, the fleet was managed with spreadsheets and chat groups. The pain was concentrated:

  • Tasks scheduled by hand: who drives which vehicle, on which route, how many kilometers today — all passed by word of mouth;
  • Compliance by memory: surveying work permits, filing notices, business licenses need periodic inspection — one miss can stop a line;
  • Assets tracked by phone: were the hard disks sent out, returned, is the data volume right — mostly by chasing people;
  • Process is a blind spot: where is a collector now, are they off-route, is the track anomalous — management had no visibility.

The system's goal: make fleet operations digital, process-driven, and auditable.

6. Engineering Highlights

  1. Single-file backend with inline migrations: no migration tool — PRAGMA table_info detects columns, missing ones get ALTER TABLE ADD COLUMN, so fast iteration still evolves safely;
  2. Chunked upload: 1MB blocks streamed to disk — big files never OOM, upload and persist overlap;
  3. Watermark + OCR in one chain: uploaded photos get a "Smart-Driving Collection" badge plus person/time/coords/address; waybill photos go through OCR to extract the SF tracking number (SF + 12 digits), then the SF API traces the route (MD5 signature);
  4. Dashboards & efficiency: overview cards + 7-day mileage trend + exceptions; efficiency stats by time / object / road type;
  5. Deployment so minimal it is art: requirements.txt lists 2 dependencies, the venv actually has ~40; uvicorn with 2 workers behind nginx — one command to go live.

7. Honest Retrospective: The Cost of Vibecoding

Speed is not magic, and this system shows the other side of Vibecoding plainly:

  • The cost of a single file: at 10,340 lines, reading, collaborating on, and unit-testing main.py all get harder;
  • Plaintext secrets: SF Express / AMap / Fengtu / DeepSeek keys sit in code or config as literals, and the default password is a shared constant — fine for an MVP, needs a rework before production;
  • Declared vs installed dependencies drift: 2 declared, ~40 installed, with try/except ImportError degrading gracefully at each layer;
  • Dev artifacts shipped: an AI-tool permission config made it into the build output, and a Vim swap file sits next to the source — fast, but no time to tidy up.

This mess is the norm for rapid systems. What matters is not pretending it away, but knowing where it lives and when the debt must be repaid.

9. PM Retrospective: Five Judgments Worth Stealing

  1. Build the vertical slice first, then spread the feature surface: v1 was only "create task → execute → dashboard" — if it can demo, it can be discussed;
  2. Make compliance an inspection checklist, not a document: surveying permits and filing notices are hard industry gates; productized, they become a daily executable list;
  3. The state machine is the backbone of any process system: settle states and transitions first; pages and dashboards are just its projections;
  4. Capitalize the process: tracks, annotations, audit logs, and a version roadmap make every operation replayable and reviewable;
  5. Know when to repay technical debt: two days solves "it works"; productionization solves "it holds up" — document the mess and repay it on a schedule.

Closing

Can a shippable business system be vibecoded in two days? Yes. But the real value is not those two days — it is the three months after, when this system kept running with a real fleet, being used and iterated. Vibecoding does not change "how fast you write code"; it changes the distance from an idea to a usable product — and that is what a product manager should care about most.
